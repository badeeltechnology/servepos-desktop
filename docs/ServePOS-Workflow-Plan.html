3. Order Status Lifecycle

Open → Preparing → Ready to Serve → Invoiced → Paid (Completed)
Status What happened Who changes it What prints Visible on Coordinator?
Open Order placed System (auto) KOT + Prep Doc (auto) Yes
Preparing Kitchen started Coordinator / Cashier — Yes
Ready to Serve Food ready, waiting for waiter Coordinator / Cashier Waiter notification Yes
Invoiced Invoice given to customer Cashier (prints invoice) Invoice Yes
Paid (Completed) Cashier confirmed payment Cashier only Receipt (auto) No — removed from view
Customer feedback: All orders stay visible on the Coordinator Screen until they reach Paid/Completed status. This way the coordinator always has a full picture of what is happening — they can check with waiters if any order is stuck at "Ready to Serve" or "Invoiced" for too long.

Receipt RECEIPT Auto on payment Full order + payment method + change + waiter Configurable Default: Receipt printer

Print Settings (Admin Page)

All print routing is configurable in the Settings page:
  • Printer assignment — Choose which printer for each document type
  • Auto vs Manual — Choose whether each document auto-prints or requires a button click
  • Enable/Disable — Turn off any print type if not needed
  • KOT routing — Route by item group to different kitchen/bar printers

  • Floor plan can be updated anytime in ERPNext — changes sync to all terminals

7. User Roles & Permissions

Cashier

  • Full POS screen access
  • Take orders + assign waiter
  • Accept/reject waiter orders
  • Print Invoice
  • Confirm payments (cash/card)
  • Mark order status (all)
  • Print receipts
  • Void orders
  • Access coordinator screen
  • Close shift + reports

Coordinator

  • Coordinator screen only
  • View all active orders
  • View order details & items
  • Mark as "Preparing"
  • Mark as "Ready to Serve"
  • ✗ Cannot confirm payments
  • ✗ Cannot print invoice/receipt
  • ✗ Cannot void/edit orders
  • ✗ Cannot access POS screen

Waiter (Mobile App)

  • Take orders on mobile
  • View own order statuses
  • Receive "Ready to Serve" alerts
  • Cancel pending orders
  • ✗ Cannot confirm payments
  • ✗ Cannot print anything
  • ✗ Cannot see others' orders

11. Implementation Phases

Phase 1 — Print System & Waiter Assignment

Get the 4 print types working + waiter selection on all orders + print settings.

  • "TAX INVOICE" → "INVOICE" / "RECEIPT" separation
  • Waiter selector dropdown in Desktop POS Cart
  • Preparation Document print template
  • Invoice print template (amounts, no payment)
  • Receipt print template (with payment + waiter name)
  • Print settings page — printer per doc type, auto/manual
  • "Print Invoice" button on orders

Phase 2 — Coordinator Screen & Notifications

Order tracking across the full lifecycle with 3 view modes.

  • Coordinator user role + login
  • Coordinator screen — Grid View
  • Coordinator screen — List View
  • Order status flow (Open → Preparing → Ready → Invoiced)
  • ERPNext status update API
  • Waiter App: polling + blinking/popup alert

Phase 3 — Floor Plan & Payment Accountability

Visual floor plan + waiter payment tracking + end-of-day.

  • ERPNext: Floor plan image upload + table positioning
  • Desktop POS: Floor Plan View on coordinator screen
  • Sync floor plan data to Desktop POS
  • Payment dialog: "Collected by Waiter" field
  • End-of-day report: open orders per waiter
  • Shift close: warn if uncleared waiter orders
  • Firebase push notifications (optional)
